## 0. First: What is this file’s job?

Before typing anything, you should think:

> “This file is the **entry point** of my backend app.”

Its responsibilities:

1. Create an Express server
2. Configure middlewares
3. Register routes
4. Connect to the database
5. Start listening for requests

That’s it. Keep this mental checklist in your head.

---

## 1. “I need a server” → Express

### Thought process

> “Node alone can’t easily handle routes. I’ll use Express.”

So your first step is importing Express and creating an app.

```js
import express from "express";

const app = express();
```

📌 **Mental rule:**
If I’m building an API → I need Express → I need `app`.

> IT is importanat to know that even tho `express()` is under a variable declaration. But in this instant it will run immediately, usually const = .. and let = ... are passive. However, with function being declare with parenthese will action immedatelly.

---

## 2. “I need to talk to a database” → Mongoose

### Thought process

> “I’m using MongoDB. I don’t want raw MongoDB syntax. I’ll use Mongoose.”
> "this is because raw MongoDB is powerful but painful for most app code. e.g.
> Fated Return

```
  db.collection("users").findOne({ email: email });
db.collection("properties").insertOne({ title, price });
```

```js
import mongoose from "mongoose";
```

You’re not connecting yet — just making the tool available.

---

## 3. “My frontend will call this API” → CORS

### Thought process

> “My frontend runs on a different port/domain. Browsers will block requests unless I allow them.”
> as by default the frontend and backend runs on a different server:
> Frontend → http://localhost:3000
> Backend → http://localhost:5000

```js
import cors from "cors";
```

Later you’ll **use** it as middleware.

---

## 4. “I have secrets (DB URL)” → dotenv

### Thought process

“I should NOT hardcode passwords or URLs. I’ll use environment variables.”

**dotenv** is a small Node.js library that lets you load **environment variables** from a file called `.env` into my application. Which is good senstive data.

`config()` is a function provided by the dotenv library.

```js
import dotenv from "dotenv";

dotenv.config();
```

📌 **Mental rule:**
Anything secret → `.env` file → `process.env`

---

## 5. “I want clean code” → Separate routes

### Thought process

> “If I put all routes here, this file will get messy. I’ll split them.”

So you import route files:

```js
import propertyRoutes from "./routes/properties.js";
import authRoutes from "./routes/auth.js";
```

Each of these files exports an Express router.

---

## 6. “Requests come as JSON” → Middleware

### Thought process

> “Most APIs send JSON. Express doesn’t parse it by default.”

**CORS (Cross-Origin Resource sharing)**

> CORS controls which websites are allowed to talk to my backend API from a browser.

```js
app.use(express.json());
```

And:

```js
app.use(cors());
```

📌 **Mental model:**
Middleware = things that run **before** routes.

Order matters:

1. Middleware
2. Routes
3. Error handling

---

## 7. “Connect URLs to routes”

### Thought process

> “If a request starts with `/api/properties`, send it to the property routes file.”

```js
app.use("/api/properties", propertyRoutes);
app.use("/api/auth", authRoutes);
```

So:

- `/api/properties` → `routes/properties.js`
- `/api/auth/login` → `routes/auth.js`

This keeps your app modular.

---

## 8. “Test if server is alive” → Root route

### Thought process

> “Let me add a simple route to confirm the API works.”
> When someone makkes an HTTP GET request to `/`, run this function and send bacak a response.
> Work flow: npm start > `package.json` "start":"node server.js" > const app = express() > server waits for requests > browsere / frontend / Postman makes GET request / app.get("/") runs

```js
app.get("/", (req, res) => {
  res.send("API is running");
});
```

This is a **health check**.

---

## 9. “Now connect to MongoDB”

### Thought process

> “Before handling requests, my DB must be connected.”

```js
mongoose
  .connect(process.env.MONGO_URI)
  .then(() => console.log("MongoDB connected"))
  .catch((err) => console.error(err));
```

📌 Why `.then()`?
Because DB connection is **async**.

---

## 10. “Start the server”

### Thought process

> “Everything is set. Now listen for requests.”

```js
app.listen(5000, () => {
  console.log("Server running on port 5000");
});
```

This is always the **last step**.

## Mental checklist you should memorize 🧠

Every Express backend entry file answers these questions:

- ❓ How do I create the app? → `express()`
- ❓ How do I parse requests? → `express.json()`
- ❓ How do I allow frontend access? → `cors()`
- ❓ Where are my routes? → `app.use(...)`
- ❓ Where is my DB? → `mongoose.connect()`
- ❓ How do I start it? → `app.listen()`

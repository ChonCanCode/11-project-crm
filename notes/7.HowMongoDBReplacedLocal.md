# 1️⃣ Big Picture: What this app is doing

**Before (old version)**

```
React → local .json file → UI
```

- Data lived in the frontend
- No authentication
- No real database
- Data reset on refresh/build

**Now (current version)**

```
React (Properties.tsx)
   ↓ HTTP request (fetch)
Express API (server.js)
   ↓ Mongoose
MongoDB (Property collection)
```

This separation is called **client–server architecture**.

---

# 2️⃣ Why this folder structure exists

## 📁 `backend/` (Node + Express + MongoDB)

Purpose:
👉 **Owns data, authentication, business logic**

```
backend/
│
├── models/        ← MongoDB schemas (data shape)
├── routes/        ← API endpoints
├── authMiddleware.js ← JWT protection
├── server.js      ← App entry point
└── .env           ← Secrets (DB URL, JWT key)
```

This keeps:

- Database logic ❌ out of React
- Secrets ❌ out of frontend
- API reusable for web/mobile apps

---

## 📁 `src/pages/` (React pages)

Purpose:
👉 **UI + user interaction**

```
pages/
├── Properties.tsx  ← Shows data
├── Adding.jsx      ← Adds data
└── home.jsx
```

## 🔹 `server.js` – the starting point


### What server.js does

1. Creates Express app
2. Connects to MongoDB
3. Registers routes
4. Starts the server

### Key lines explained

```js
app.use(express.json());
```

✔ Allows reading JSON from `req.body`

```js
app.use("/api/properties", propertyRoutes);
```

Means:

```
GET /api/properties → routes/properties.js
POST /api/properties → routes/properties.js
```

```js
mongoose.connect(process.env.MONGO_URI);
```

✔ Connects to MongoDB Atlas or local MongoDB
✔ Replaces local `.json` files entirely

## 🔹 `models/Property.js` – MongoDB Schema

This replaces your old `properties.json`.

```js
const propertySchema = new mongoose.Schema({
  street: String,
  city: String,
  postcode: String,
  tenant: String,
  rent: Number,
  status: String,
});
```

### What this means

- Defines **shape of data**
- MongoDB collection will be: `properties`
- Each document looks like:

```json
{
  "_id": "...",
  "street": "Main St",
  "city": "London",
  "rent": 1200
}
```

```js
module.exports = mongoose.model("Property", propertySchema);
```

✔ Creates a **MongoDB model**
✔ Lets you do:

```js
Property.find();
Property.save();
```

---

## 🔹 `routes/properties.js` – API logic

This file replaces **reading/writing JSON manually**.

### GET all properties

```js
router.get("/", async (req, res) => {
  const properties = await Property.find();
  res.json(properties);
});
```

Equivalent to:

```
SELECT * FROM properties;
```

✔ Fetches from MongoDB
✔ Sends JSON to frontend

---

### POST new property

```js
router.post("/", async (req, res) => {
  const property = new Property(req.body);
  await property.save();
  res.status(201).json(property);
});
```

✔ Saves data into MongoDB
✔ No JSON file editing
✔ MongoDB auto-generates `_id`

## 🔹 `models/User.js` + `routes/auth.js`

These handle **authentication**.

### Why passwords are hashed

```js
bcrypt.hash(req.body.password, 10);
```

✔ Security best practice
✔ DB never stores plain text passwords

---

### JWT flow

```js
const token = jwt.sign({ id: user._id }, process.env.JWT_SECRET);
```

This creates a **login token**, stored in:

```js
localStorage.setItem("token", token);
```

Frontend sends it back on every request.

---

## 🔹 `authMiddleware.js` – Route protection

```js
const token = req.headers.authorization?.split(" ")[1];
```

Reads:

```
Authorization: Bearer <token>
```

```js
jwt.verify(token, process.env.JWT_SECRET);
```

✔ Confirms user identity
✔ Prevents unauthorized access

(You’re not using it yet on properties, but you can.)

# 4️⃣ Frontend: `Properties.tsx` explained

This is where **React replaces the old JSON import**.

---

## 🔹 TypeScript type

```ts
type Property = {
  _id: string;
  street: string;
  city: string;
  rent: number;
};
```

✔ Matches MongoDB schema
✔ `_id` comes from MongoDB automatically

---

## 🔹 State

```ts
const [properties, setProperties] = useState<Property[]>([]);
```

✔ Replaces static JSON data
✔ Starts empty, fills after API call

---

## 🔹 `useEffect` (runs once)

```ts
useEffect(() => {
  fetch("http://localhost:5000/api/properties", {
    headers: {
      Authorization: `Bearer ${localStorage.getItem("token") || ""}`,
    },
  })
```

### What happens here

1. React loads page
2. `useEffect` runs
3. Fetch request goes to Express
4. Express talks to MongoDB
5. Data returns as JSON
6. `setProperties(data)`
7. UI re-renders

---

```tsx
  <tr key={property._id}>
```

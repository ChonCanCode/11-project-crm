# Big Picture (Before Any Code)

You’re building a **Node.js + Express + MongoDB API**.

Think of it like a restaurant:

| Concept             | Backend Equivalent                  |
| ------------------- | ----------------------------------- |
| Restaurant building | `server.js`                         |
| Menu                | Routes (`auth.js`, `properties.js`) |
| Kitchen rules       | Models (`User.js`, `Property.js`)   |
| Ingredients storage | MongoDB                             |
| Customers           | Frontend / Postman                  |

---

## Folder Structure — WHY it exists

backend/
├── models/ ← How data looks (MongoDB schemas)
│ ├── User.js
│ └── Property.js
│
├── routes/ ← API endpoints (/login, /properties, etc.)
│ ├── auth.js
│ └── properties.js
│
├── server.js ← App entry point (starts everything)
├── .env ← Secrets (DB password, JWT secret)

---

### Why split files?

Because one file doing everything becomes **unmaintainable**.

**Rule of thumb:**

- **Models** → Data shape
- **Routes** → URLs & logic
- **server.js** → Wiring everything together

---

## 1️⃣ `server.js` — The Entry Point (The Brain)

This is always written first.

### What this file does

✔ Starts Express
✔ Connects to MongoDB
✔ Registers routes
✔ Listens on a port

---

### Step-by-step thinking (how you would write it)

#### Step 1: Create the server

`const express = require("express");`
`const app = express();`

> “I need a web server.”

---

#### Step 2: Allow JSON + frontend access

`app.use(express.json());`
`app.use(cors());`

> “My frontend will send JSON and run on a different domain.”

---

#### Step 3: Load environment variables

`require("dotenv").config();`

> “Secrets should not be in code.”

---

#### Step 4: Connect MongoDB

`mongoose.connect(process.env.MONGO_URI);`

> “I need persistent data storage.”

---

#### Step 5: Plug in routes

`app.use("/api/auth", authRoutes);`
`app.use("/api/properties", propertyRoutes);`

> “When someone hits `/api/auth`, use `auth.js`.”

This is **route delegation**.

---

#### Step 6: Start server

`app.listen(5000);`

> “Now listen for requests.”

---

## 2️⃣ Routes — What the API can DO

Routes answer the question:

**“What happens when someone hits this URL?”**

---

### `routes/properties.js`

#### What this file does

Handles:

- GET `/api/properties`
- POST `/api/properties`

---

### Why `express.Router()`?

Because you don’t want everything in `server.js`.

`const router = express.Router();`

This creates a **mini Express app**.

---

### GET all properties

`router.get("/", async (req, res) => {`
`  const properties = await Property.find();`
`  res.json(properties);`
`});`

**Thinking process:**

- Someone asks for properties
- Fetch from database
- Send back JSON

---

### POST new property

`router.post("/", async (req, res) => {`
`  const property = new Property(req.body);`
`  await property.save();`
`  res.status(201).json(property);`
`});`

**Thinking process:**

- User sends property data
- Create MongoDB document
- Save it
- Return it

---

### Export router

`module.exports = router;`

> “Let `server.js` use this file.”

## 4️⃣ Models — How Data Looks in MongoDB

Models answer:

**“What does a User / Property look like?”**

---

### `models/User.js`

`const userSchema = new mongoose.Schema({`
`  email: String,`
`  password: String,`
`  role: { type: String, default: "user" },`
`});`

This is MongoDB’s **blueprint**.

> “Every user document MUST look like this.”

---

### `models/Property.js`

`const propertySchema = new mongoose.Schema({`
`  street: String,`
`  city: String,`
`  rent: Number,`
`  status: String,`
`});`

> “Every property has these fields.”

## How YOU Would Write This Yourself (Mental Checklist)

When building **ANY backend feature**:

- Do I need data?
  → Create a **model**

- Do I need an API endpoint?
  → Create a **route**

- Does the server know about it?
  → Register route in **server.js**
